New vs. the Oct 17 scan

  • The Datadog RUM SDK version is now confirmed as v2.18.0, loaded from the legacy unversioned CDN URL. The init has no env, uses v2 option names, samples 5% in production, and only starts after cookie consent. Session Replay needs SDK v3+, so upgrading the SDK is a concrete first step.
  • GCP details: public GitHub Actions deploy character sheets to gs://roll20-cdn in GCP project roll20-actual using google-github-actions/auth. cdn.roll20.net sits on a Google Cloud load-balancer IP.
  • Demiplane runs on AWS us-west-2 behind production ALBs (demiplane-prod-alb-apiv4, demiplane-prod-alb-utils-api) and CloudFront. The client is Next.js 16.2 / React 19 (Turbopack) with a self-hosted Hasura GraphQL API over WebSockets (urql). No RUM, APM or error-tracking SDK was found in any of the 42 bundles.
  • CircleCI and Cypress move from LinkedIn-only (Medium) to High: both appear in public repo config. Vitest, ESLint, Prettier, Bun and Vite are confirmed in the Beacon sheet code.
  • DriveThruRPG uses Symfony + API Platform for its newer codebase and is sunsetting the legacy PHP marketplace. Its SPF points to an AWS EC2 address. Zendesk is shared with Roll20 (roll20drivethrurpg.zendesk.com).
  • New tools found: WordPress (Automattic) + Jetpack for the blog, Discourse 3.1 for the Demiplane forums, Webflow DNS for www.demiplane.com, MediaWiki, PayPal Express (Ruby fork pushed Jun 2026), Braintree and Swell flags on Demiplane, Paddle and Plausible on Dungeon Scrawl, reCAPTCHA, the Discord Embedded App SDK, and Google Cloud DNS for roll20teams.net.
  • Corrections: a “rollbar” string on the blog was a CSS scrollbar false positive, so no Rollbar is present. The GitHub org “demiplane” is an unrelated 2018 C# project and was excluded. Nothing public names an on-call or paging tool.
  • Devices: the only device named publicly is a 2022 MacBook Air, used as a VTT test machine in the Apr 2026 blog. Job posts offer an “equipment allowance” but name no standard laptop.

Caveats

  • Outside-in only: server-side tooling (APM agents, log pipelines, paging) can’t be seen from public pages. A negative result does not prove absence.
  • drivethrurpg.com, help.roll20.net, wiki.roll20.net and app.roll20.net return Cloudflare bot challenges to scripted fetches. DriveThruRPG page source was not inspected; its job text comes from search-indexed copies of the jobs page.
  • LinkedIn skills are self-reported and often reflect earlier employers. The saved li_*.html pages only show public, logged-out profile fragments (no skills sections). People associations rely on the Oct 17 LinkedIn sweep (82 of 113 profiles).
  • The DriveThruRPG DevOps listing was first posted in Nov 2022 and was still shown on the jobs page in search results. 2017 and 2018 Roll20 job posts are archival and marked Medium or Low.
  • IP-to-provider mappings (e.g. 18.216.116.235 → AWS EC2; 35.241.21.104 → Google Cloud LB) are inferred from published provider ranges and marked [inference].
  • Datadog integration status comes from docs.datadoghq.com pages fetched Oct 18, 2026. The Hasura Cloud integration only covers Hasura Cloud; self-hosted Hasura would need OpenTelemetry or Prometheus.
  • The Datadog RUM client token and application ID that appear in Roll20’s public page source are deliberately left out of this report.
  • Devices: the only device mentioned is the MacBook Air test machine. No public photos of staff laptops were reviewed, and no fleet is assumed.
